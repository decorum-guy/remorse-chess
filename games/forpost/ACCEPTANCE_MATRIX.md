# ФОРПОСТ — сводная матрица приёмки

## Статус и границы доказательств

**Полная самостоятельная приёмка и публичный выпуск не завершены. Самостоятельных браузерных проходов: 0. Завершённых автоматических UI-раундов: 4, все не приняты целиком.** Эта матрица сопоставляет обязательные ID из [IMPLEMENTATION.md](IMPLEMENTATION.md) с фактическими тестами и завершёнными журналами. Формулировки сценариев F01–F22 и названия этапов E01–E16 сохранены. Наличие реализации или написанного e2e-сценария не считается выполненным прохождением.

Документ основан на непосредственно прочитанных исходниках, отчётах и журналах данной рабочей копии. Перечень оставшихся проверок — сопоставление этих доказательств с нормативными критериями, а не утверждение об обнаруженной ошибке в каждом непроверенном месте. Первоначальный mapping был read-only. Последующее подтверждённое исправление временного бота и его отдельная проверка добавлены ниже с новым хешем.

Итоговый SHA-256 совокупности 18 файлов `src/core/*.ts`:

`14d49d29954d0f7f427feea026beb23113699ff8ecb36ec4480f61f339a61e68`

На этом ядре выполнены **62 целевых теста** и две матрицы эквивалентности оптимизации: 2 556 полных World JSON побайтово равны baseline `22a7132d…`, 468 безопасных видов структурно равны. Точный performance assertion на текущем хеше **не пройден: p99 17.939249 мс**; подробности — [CORE_PERFORMANCE.md](CORE_PERFORMANCE.md). Ранее на `22a7132d…` прошли 59 тестов после исправления временного бота; NETWORK R5/RTT R3 ниже относятся именно к нему. На `f2fe9304a57859a8a7767f49f31df9bfba31dfe1e19c0d4de63088bcca367e08` выполнены **57 целевых тестов** и прежняя R4 **72/72 матчей, 0 технических ошибок**. Час нагрузки на текущем хеше ещё не запускался. Эти доказательства не заменяют действия через интерфейс, проверку на телефоне и публичную доставку.

В таблицах «подтверждено автоматически» относится только к названным assertions. «Не принят» относится к полному нормативному пункту. Пункт не получает общий PASS, если обязательная UI-проверка или другая часть его критерия отсутствует. Измеренный провал производительности обозначен отдельно; непроведённая проверка не названа провалом программы.

## UI, дефекты и выпуск

`F01` в [UI_COVERAGE.md](UI_COVERAGE.md) обозначает элемент клавиатурного движения; `F01` из IMPLEMENTATION означает дуэль 2:0. Это разные пространства ID. Настоящая таблица использует **нормативные ID IMPLEMENTATION**. Проверка интерактивных элементов сохраняется отдельно, с состояниями normal, hover, pressed, selected, disabled с причиной, waiting, success и error; hover к touch не применяется.

Для UI остаются все соответствующие наблюдения мышью, клавиатурой и touch, выбор/выделение юнитов, фокус и прицел, очередь/отмена/продажа, состояния ожидания и ошибок, потеря фокуса, отпускание огня, поворот, малый экран, 130% текста, WebGL→2D, повтор партии и возврат в меню. Проверки исходных сценариев исправленных дефектов следует отмечать в [ACCEPTANCE.md](ACCEPTANCE.md); автоматический регрессионный тест и визуальная перепроверка должны оставаться отдельными полями.

Наблюдавшиеся ограничения доступа описаны в [STATUS.md](STATUS.md): браузерный процесс не видит loopback изолированного сервера; выход процесса из ограничения был автоматически отклонён (`sandbox_approval:false`); локальный Chromium отсутствует, скачивание Playwright Chromium вернуло HTTP 403. Физический телефон и канал фактического прослушивания не проверялись. Эти ограничения объясняют отсутствие наблюдений, но не переводят непроведённую приёмку в успешную.

Публичный выпуск также требует реального доступа и штатного развёртывания realtime-сервиса на хосте; успешный localhost HTTP smoke не является опубликованной игрой. До закрытия E15/E16, максимального p99, актуальной продолжительной нагрузки и обязательных телефонных/сетевых условий статус полной готовности остаётся **не принят**. Новые завершённые проверки должны добавляться с их собственными source/artifact IDs и журналом, без переноса старого PASS на изменённую сборку.
