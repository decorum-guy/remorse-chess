# «Форпост»: передача ядра симуляции

Этот документ описывает фактические исходники и выполненные проверки чистого ядра. Технические симуляции ниже **не являются браузерными прохождениями** и не подтверждают публикацию игры.

## Зафиксированные исходники

Ядро: 18 файлов TypeScript в `src/core/`. Итоговый агрегированный SHA-256:

`14d49d29954d0f7f427feea026beb23113699ff8ecb36ec4480f61f339a61e68`

Этот хеш включает исправление временной стратегии бота и эквивалентную оптимизацию видимости/движения. На нём завершены 62 целевых теста, две матрицы сравнения с baseline, измерения максимальной сцены и новая серия **R5: 72/72 матчей, 0 технических ошибок**. R5 использует отдельную копию commit `e88be1a203142a40801195cbfad1eafe8ea47574`, tree `f3ff57573fb9ce7f3399e6cc0312aee56160943e`; точный [отчёт серии](qa/core-series-r5.json) содержит команду, хеши и все результаты. Предыдущая R4 на `f2fe9304…` и NETWORK R5/RTT R3 на `22a7132d…` сохраняют прежние идентификаторы. Точные измерения максимальной сцены и ограничения: [CORE_PERFORMANCE.md](CORE_PERFORMANCE.md).

Хеш рассчитывается последовательным добавлением пути каждого `games/forpost/src/core/*.ts` в лексикографическом порядке и затем точных байтов этого файла. Это хеш исходников ядра, а не git commit или опубликованная ревизия.

Правила, карта и бот имеют отдельные версии в `constants.ts`. В сетевой среде executable artifact дополнительно фиксируется общим runtime; сохранённая комната должна продолжать использовать прежний исполняемый артефакт.

## Публичный API

Все интеграционные экспорты находятся в `src/core/index.ts`.

| API | Назначение |
|---|---|
| `createWorld(options)` | Равные команды A/B, N=1/2/3, явные люди/боты, карта, seed, сторона, режим |
| `stepWorld(world, inputs)` | Ровно один авторитетный шаг 1/30 с; изменяет и возвращает тот же World |
| `applyAction(world, participantId, payload)` | Проверка принадлежности, ресурсов, геометрии и идемпотентных actionId |
| `viewForPlayer(world, participantId)` | Единственная разрешённая проекция для клиента и политики бота |
| `serializeWorld` / `deserializeWorld` | Полное серверное сохранение с проверкой версии; запрещено передавать клиенту обычного матча |
| `setController` / `resetInputStream` | Временное управление ботом и новая последовательность ввода без сброса оружейного cooldown |
| `setRewindEstimate` | Половина RTT, ограниченная 150 мс и существующими тиками истории |
| `buildEligibility` / `refundPreview` | Те же причины отказа и расчёт возврата, которые использует сервер |
| `getMap` / `validateMap` | Все три карты, их отражения и проверка путей при занятых площадках |
| `createTutorialWorld(lesson)` / `tutorialProgress` | Семь изолированных упражнений, продвигающихся по реальным игровым условиям |

`Input.aimX/aimZ` — направление. `inputSeq` возрастает внутри одной controller generation. `firePressSeq` даёт одну допустимую попытку выстрела, без воспроизведения накопленных нажатий. Истечение ввода — 8 тиков: `ceil(30 × 0.25)` по общему правилу округления сроков.

В сетевом `createWorld` runtime передаёт приватный `idSalt` из 32 случайных байтов. Он сохраняется только в серверном World. Идентификаторы создаваемых объектов имеют непрозрачный суффикс, чтобы разрывы общего счётчика не выдавали чужие скрытые покупки. Детерминированный fallback предназначен для локального обучения и технических фикстур.

Статус `participant.builderPaused` доступен своей команде. Команда `resumeBuild` продолжает очередь после явного приказа строителю остановиться или вернуться.

## Реализованные системы

Симуляция содержит три точные карты FP01/FP02/FP03; движение, коллизии и обход препятствий; три оружия и три инструмента; бойца, строителя и личных боевых дронов; восемь построек; личные кредиты, командный заряд, станции, сеть и приоритет мощности; очереди, продажу и возвраты; мосты и эвакуацию; маршруты, сопровождение и разгрузку; возрождение и защиту; результаты операций, дополнительное время и ограниченный матч.

Навигационные графы и поля пути к общей цели кэшируются как производные данные. Они не входят в сохранение и не меняют авторитетное состояние при чтении. Кэш видимости имеет ограниченную область применения: единая геометрия фазы выстрелов либо одного чтения view. После движения и изменения геометрии он не используется повторно.

Боты получают `WorldView`, используют свой воспроизводимый поток случайности и обычные команды. Роли сопровождения, захвата и атаки распределяются по месту участника. Профили задают планирование, реакцию и ошибку прицела. Из этих прогонов нельзя делать вывод о силе бота относительно человека.

## Проверенная приватность

- Вражеские мобильные объекты отсутствуют за пределами разрешённой видимости; история жизни, приказы, магазин и точный срок защиты не передаются.
- У видимого бойца доступны наблюдаемые оружие и boolean защиты; точный `protectedUntil` относится только к своей команде.
- Публичный транспорт передаёт маршрут, положение, HP и прогресс. Чужие `escorted`, `speed`, `unloadTicks`, `lastDamageTick` отсутствуют. Начало и прерывание разгрузки не передаются противнику как публичные события.
- Владение станцией и прогресс её захвата публичны согласно DESIGN §7. Состав скрытых захватчиков не передаётся.
- Видимые чужие постройки не раскрывают очередь, внутренние таймеры и настройки. Память здания обновляется только при наблюдении.
- Чужие дым и барьер не раскрывают владельца и точный `expiresTick`.
- `event.point` и `event.end` содержат только X/Z. Проекция событий повторно перечисляет разрешённые поля явно.
- Скрытые выстрелы дают только допустимые сегменты трассера и, в пределах слышимости, восьмисекторный звук без ID/координаты. Скрытая смерть юнита не подтверждается отдельным звуком смерти.
- Слепой урон не создаёт стрелку hit marker по скрытой цели или барьеру. Полные личные боевые статистики доступны только после матча.
- Последовательности событий отдельные для каждого наблюдателя. Полный World и его приватные счётчики никогда не являются wire-view.

### Максимальная сцена

`tests/core-benchmark.ts` создаёт полную сцену: 6 бойцов, 6 строителей, 12 дронов, 2 транспорта, 30 построек, 6 активных строительных работ и 24 источника одновременного огня. Проверяются три варианта: 6 облаков дыма, 6 барьеров, смешанные 3+3. Положения юнитов законны. Каждый sample восстанавливает полный состав и готовность огня, поэтому смерти и cooldown не снижают нагрузку незаметно. Это намеренно плотная нагрузочная фикстура, а не обычный непрерывный матч.

В предыдущей исходной фикстуре некоторые юниты пересекали площадки, а часть турелей не была подключена. Перед итоговым измерением исправлена сама фикстура: валидируется `illegalUnits=[]`, наблюдается 24 стреляющих источника и 6 работ.

**Цель p99 работы шага <16.667 мс пока не подтверждена и считается непройденной.** Последний точный assertion на `14d49d29…` завершился с exit 1: дымовая сцена — **17.939249 мс**. В двух standalone-повторностях текущего ядра p99 дыма составил 25.546/18.556 мс, барьеров — 19.481/9.727 мс, смешанной сцены — 10.251/10.039 мс. Медианы уменьшились примерно на 34–64% относительно последовательно измеренного `22a7132d…`; это не общий PASS. Полные ABBA-результаты, условия, CPU, холодные шаги и hashes находятся в [CORE_PERFORMANCE.md](CORE_PERFORMANCE.md). Для этих сравнений тяжёлые проверки нашей команды не выполнялись одновременно; изоляция общего хоста не заявляется.

Историческое измерение `4e715bab…` дало p99 51.117/27.283/24.633 мс для дыма/барьеров/смешанной сцены. Оно выполнено в общем контейнере параллельно серии 72 матчей; его нельзя называть чистым изолированным сравнением или измерением другого сервера.

## Границы этой передачи

Это проверка ядра и технических симуляций. Реальный браузерный проход, touch/поворот экрана/фокус, WebGL→2D, UI-состояния всех элементов, сетевые RTT/loss/reconnect, часовой runtime-load, CI, публичный каталог и опубликованная ревизия относятся к интеграционному отчёту. Этот документ не объявляет их выполненными.

Команды воспроизведения из корня репозитория:

```sh
npx vitest run --config games/forpost/vitest.config.ts games/forpost/tests/core-rules.test.ts games/forpost/tests/core-privacy.test.ts games/forpost/tests/core-tutorial.test.ts games/forpost/tests/core-optimization.test.ts
FORPOST_SERIES=1 npx vitest run --config games/forpost/vitest.config.ts games/forpost/tests/core-series.test.ts --reporter=verbose
FORPOST_PERF=1 npx vitest run --config games/forpost/vitest.config.ts games/forpost/tests/core-load.test.ts --reporter=verbose
npx eslint games/forpost/src/core games/forpost/tests/core*.ts
npx tsc --noEmit -p games/forpost/tsconfig.json
```

`FORPOST_PERF=1` включает явный assert целевого p99; успешная обычная механическая проверка сцены без этого флага не означает прохождения performance-gate.
