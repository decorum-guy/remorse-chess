# Сдвиг

**ТЗ на законченный выпуск v1 для Iva Games** · **Shift** · `shift`

Две команды охотятся за одной батареей. Пилоты бегут по этажу и стреляют, штурманы играют на том же этаже в пятнашки. Вместе с комнатой переезжает всё, что находится внутри. Пилот может открыть себе путь стрельбой, а штурман может увести всю перестрелку в другой коридор.

Задача разработчика — законченный браузерный командный матч, две полноценные роли, три арены, смешанные команды с ботами, интерактивное обучение и визуал 2.5D. Основание — выбранная владельцем концепция из переписки. Параметры ниже задают первые играбельные правила и уточняются только по результатам проверок.

## 1. Продукт

| Параметр | Решение v1 |
| --- | --- |
| Состав | 2×2 или 3×3. В каждой команде ровно один штурман и один или два пилота. От двух живых игроков в закрытой онлайн-комнате, остальные места можно заполнить ботами |
| Что делать | Найти батарею, взять её пилотом и зарядить свои ворота. Контроль территории хорош настолько, насколько он помогает доставке |
| Управление | Пилот — клавиатура и прицел мышью или сенсорные стики. Штурман — этаж сверху, выбор комнаты, сдвиг, метки напарникам |
| Формат камеры | 2.5D с объёмными стенами, комнатами и дронами. Геометрия правил лежит в одной плоскости. Вид пилота наклонный, вид штурмана сверху |
| Длительность | Ориентир 8–12 минут на полноценный матч |
| Практика | Один человек выбирает роль и играет с ботами. Можно пройти уроки обеих ролей и повторить любую арену |
| Языки | Русский и английский полностью. Короткие боевые сообщения читаются поверх сцены |
| Границы v1 | Закрытые комнаты и практика, одна модель импульсного оружия, три арены. Рейтинг, открытый подбор, голосовой чат и редактор карт не входят в готовность этой версии |

Принцип для плейтеста. У штурмана есть несколько осмысленных сдвигов на раунд. Пилот способен сыграть даже при пассивном штурмане, а скоординированный сдвиг резко меняет ситуацию. Первые плейтесты дают отдельную обратную связь по обеим ролям. Выход из блокаута — показать минимум три разных способа, которыми удачный сдвиг помог доставке.

## 2. Матч, состав и таймеры

| Фаза | Правило |
| --- | --- |
| Создание комнаты | Выбрать арену и формат команд 2×2 или 3×3. Клиент предлагает ровно 4 или 6 мест, сервер подтверждает соответствие формата и состава перед стартом. Настройка «Смена ролей» по умолчанию включена. Все места заполняются до старта. Ведущий расставляет команды вместе с участниками, кнопка «Случайные команды» предлагает готовую симметричную раскладку |
| Готовность | Участник видит свой цвет, позывной и первую роль. Любое изменение карты, состава, команд или режима смены сбрасывает готовность людей. При старте ростер и порядок смены фиксируются |
| Перед раундом | 7 с на ориентацию в плане. Видны стартовое положение батареи и шахты, отметки напарников и кнопки управления. Стрельба и сдвиг активны после «Старт» |
| Раунд | 75 с. Первая подтверждённая доставка даёт 1 очко команде и сразу заканчивает раунд. Если никто не доставил к дедлайну, обе команды получают 0 |
| Между раундами | 8 с. Показать причину завершения, текущий счёт, следующую роль. Сбросить позиции, здоровье, платформы и батарею до стартового состояния карты |
| Конец матча | Сразу при 3 очках или после 5 раундов в пользу лидера. Если после пятого очки равны, сыграть один решающий раунд на 45 с по тем же правилам. Равенство после него — ничья. Отчёт и быстрый реванш |

Порядок ролей — циклическая перестановка внутри команды по видимому порядку мест. При отключённой смене роли остаются исходными. В каждой команде может быть один или два игрока, предпочитающих одну роль. Раскладка и смена решаются в лобби. Назначение бота фиксируется отдельно от человеческого аккаунта.

Стартовая карта раунда одна и та же для обеих сторон. В чётных раундах команды меняют стороны, сохраняя свой цвет и счёт. Раздача первого приоритета сдвига тоже чередуется по номеру раунда. Полномочия хоста заканчиваются на организации комнаты.

## 3. Этаж как пятнашки

### 3.1. Геометрия и идентификаторы

- Игровое поле — квадрат **3×3**. Размер клетки **8×8 м**. Строка `r=0` на севере, столбец `c=0` на западе. Центр клетки на `X=8c, Z=8r`, север — `−Z`. Восемь модулей имеют постоянные ID `A,B,C,D,E,F,G,O`. Девятая клетка — шахта.
- В середине каждой из четырёх сторон комнаты есть общий дверной проём шириной **2,0 м**. Использовать одинаковый профиль стен и коллизий для всех стыков. Открытие соединяет только две неподвижные комнаты с общей гранью. На границе с шахтой, во внешней стене севера/юга и при движении модуля проём заперт.
- Западный и восточный шлюзы вне плиток стоят неподвижно. Каждый соединяется с тремя отверстиями вдоль своего края. Шахта у одного отверстия оставляет два других. Площадки командных ворот — в средней части своих шлюзов. Оба шлюза доступны физически. База не блокируется одним сдвигом.
- Модуль `O` содержит пьедестал батареи, который переезжает вместе с ним. Батарея на полу хранит `spaceId, localX, localZ`. Батарея в руках принадлежит несущему дрону.
- У каждого модуля свой внутренний рисунок укрытий, но дверной буфер глубиной 0,9 м чист. Радиус дрона 0,28 м. Обязательные коридоры внутри не уже 1,25 м. Геометрия укрытий задаётся прямоугольниками или выпуклыми полигонами, рендер, прострел и столкновения берут их из одного файла арены.

### 3.2. Команда штурмана

Разрешён сдвиг одного модуля, стоящего вплотную к текущей шахте по стороне. Запрос передаёт `roomId`, `expectedBoardRevision` и ID действия. Перемещение всегда поперечное на один тайл, ориентация модуля сохраняется.

| Параметр | Стартовое значение |
| --- | --- |
| Время переезда | 0,55 с. Весь ход — один серверный интервал |
| Кулдаун штурмана | 6 с от принятия, свой для каждой команды |
| Одновременные запросы | Сервер принимает максимум один на тик. При двух допустимых запросах на одном тике работает текущий приоритет. После успешного хода приоритет получает другая команда. Более ранний допустимый ход всегда выигрывает у позднего |
| Мгновенный откат | Возврат только что передвинутой комнаты обратно закрыт для всех на 2 с после окончания её движения |
| Следующий сдвиг | Пока предыдущий в пути, новые запросы отклоняются с причиной. После отказа личный кулдаун не расходуется |
| Выбор на экране | Цвет и контур доступного модуля, пустая клетка, тонкая стрелка переезда. Наведение даёт схему открытых дверей после хода. Серверное принятие запускает движение |

На начале переезда сервер закрывает стыки. На пороге каждый дрон уже принадлежит одному пространству по координате центра. Точный центр порога остаётся у последнего подтверждённого пространства. Провести ограниченную коррекцию к ближайшему свободному месту внутри него. Резервируются исходная и целевая клетки. Другие игроки остаются на неподвижной части карты, обход и открытые проходы продолжают работать.

Дроны и батарея внутри передвигаемого модуля сохраняют локальную позу и могут двигаться и стрелять внутри него. Через закрытые двери во время переезда не проходят тела, импульсы и обзор. На окончании сервер переносит модуль на целевую клетку, делает исходную шахтой и заново открывает валидные стыки. Отображение непрерывно перемещает всю комнату единым объектом. Уменьшение движения даёт фиксированную камеру и короткий переход с подсветкой старых и новых дверей.

Нейтральный объект на пьедестале, свободный объект на полу, дрон под огнём и дрон с грузом подчиняются одному правилу переноса. Отдельно проверять эти четыре случая. Сдвигать комнату с союзником и соперником одновременно разрешено.

## 4. Пилот, стрельба и батарея

### 4.1. Движение и импульсы

- `WASD` / стрелки перемещают по фиксированным осям, прицел мышью и `ЛКМ` дают выстрел. `E` взаимодействует с батареей. `Q` ставит команде метку, контекстная метка по комнате просит её сдвинуть. На телефоне левый стик — ход, правый — поворот прицела, отдельные кнопки импульса и действия. Кнопки можно переназначить.
- Скорость **4,6 м/с**, с батареей **3,6 м/с**. Диагональ нормализуется. Дроны проходят друг сквозь друга, чтобы тело игрока не запечатывало узкий проход. Укрытия и двери твёрдые. Масса и импульс визуальные, правила столкновений предсказуемы в одной плоскости.
- У дрона **3 HP**. Один импульс снимает 1 HP, дальность **12 м**, кулдаун **0,34 с**. Направление проверяется сервером. Луч прекращается на первом препятствии или первом вражеском дроне. Союзники прозрачны для импульса, урон своим отключён. При прямом обмене обоим может пройти смертельный выстрел на одном тике.
- Выбитый дрон оставляет батарею в текущем пространстве, показывает краткий разбитый корпус и через **2,6 с** возвращается в свой шлюз. Щит на **1,2 с**, до своего первого выстрела или выхода из шлюза, защищает от урона. Щит и место появления ясно видны противнику. Места появления разведены и вмещают две модели.
- Вход в комнату, вход на площадку, выбор цели выстрела и перенос определяются серверной геометрией, включая остаток шага после пересечения границы. Эффект импульса не проходит дальше подтверждённой точки попадания.

### 4.2. Батарея и доставка

1. В начале она лежит на пьедестале комнаты `O`. Пилот при дистанции до **0,9 м** и прямой линии нажимает `E`. Одно взятие на один объект. На одном тике выигрывает ближайший допустимый пилот, при равенстве — очередность мест, вращаемая по номеру раунда.
2. Носитель всё ещё стреляет. `E` или повреждение до нуля сбрасывает батарею на последнюю допустимую точку пола рядом с дроном. Она видна из доступной области. В неподвижном состоянии через **7 с** возвращается на текущий пьедестал `O`. Если перенос произойдёт за этот интервал, батарея движется с комнатой. Положение на пьедестале таймер не запускает.
3. Для сдачи пилот с батареей должен непрерывно держать центр дрона на своей площадке **0,65 с** и остаться активным. Панель видит прогресс. Сброс, выход из зоны или ноль HP обнуляют прогресс. Выстрел и перемещение внутри площадки допустимы. Доставка автоматически подтверждает очко.
4. Порядок одного тика: завершить переезды, возвраты батареи и респауны с пришедшим сроком → принять новый сдвиг и обновить двери → переместить пилотов → разрешить взаимодействия → вычислить все лучи и применить урон → проверить засчитанную доставку → обработать истечение раунда. Поэтому выбитый на тике завершения носитель не забивает. Успевшая на последнем тике целая доставка засчитывается.

Сдвиги и выстрелы — разные профессии, но общая победа учитывает доставку. На финальном экране у пилота показываются доставка, перехваты и точные попадания. У штурмана — перевозки батареи в комнате, успешные сдвиги с союзником и события открытия стыков. Килл-счёт не заменяет результат и не даёт очков за раунд. Рядом с цифрами — запись вида «Лис передвинул комнату, Даша вынесла батарею».

## 5. Видимость и взаимодействие команды

- План комнат, номера модулей, шахта и текущее состояние стыков открыты. Пилоты видят свою позицию и союзников. Врага видно на тактическом плане только после серверного обнаружения хотя бы одним пилотом команды. Обнаружение — прямая линия с центром дрона в пределах **13 м** через разрешённые стыки, с отсечением стенами.
- Штурман видит план целиком, все позиции своей команды и её подтверждённые обнаружения противника. Камера пилота и тактический вид получают одну командную информацию о врагах. Для скрывшегося противника передавать единственное последнее обнаружение и возраст до **2 с**, затем удалить маркер. Точные скрытые позиции, HP, цель и батарея у скрытого вражеского носителя отсутствуют в трафике и в журналах клиента.
- При свободной батарее команда знает только модуль объекта, а точку получает при обнаружении. На видимом носителе знак батареи. При взятии показать событие «Батарею несут синие / янтарные», дальнее скрытое движение позиции из этого сообщения не выводится.
- Метки команды. «Сдвинь» привязана к ID комнаты и переезжает с ней. «Смотри сюда» привязана к доступной точке, «Батарея» к увиденному событию. Видимая жизнь метки **4 с**, максимум три за 10 с на место. Все виды и звуки врага фильтрует сервер. Соперник не получает метки.
- В перерыве показать на схеме путь последней батареи и три решающих события по правилам видимости матча. После финала можно раскрыть общий журнал, сформированный из закрывшегося матча. В v1 достаточно ключевых событий и схемы, без записи свободной камеры.

Обрыв связи. Через 250 мс сервер гасит движение и стрельбу. Через 10 с место может вести отмеченный «Бот замещает», используя тот же публичный для роли вид. Ростер и человеческое место сохраняются. По возврате владельца одна серверная смена эпохи отменяет команды помощника и возвращает управление. Возврат включает снимок текущей роли, карты, таймеров и последних подтверждённых меток.

## 6. Арены релиза

Блок-аут строится из соглашения о координатах выше. В каждой строчке символы перечислены с запада на восток. `□` — шахта. Центр с `O` содержит батарею. Модули одной темы делят стены и двери. Парные модули `A/E`, `B/D` и `F/G` выступают зеркалами внутри стартового плана. `C` и `O` симметричны по местной оси запад–восток.

| Арена | Север / середина / юг | Особенность и сборка комнат |
| --- | --- | --- |
| Крановый цех | `B C D` / `A O E` / `F □ G` | В `O` две центральные низкие тумбы по сторонам пьедестала и длинные линии через стыки. В `A/E` диагональные маршруты из станин. `F/G` открыты для быстрой перестройки снизу. Визуал жёлтых крановых балок и тёмного литого пола |
| Калибровка | `F □ G` / `B O D` / `A C E` | `B/D` с двумя выборочными укрытиями в середине, из-за которых выгодно менять сторону подхода. `O` — четыре угловых пилона с чистым центром. Нижний `C` — короткое прикрытие и два выхода. Визуал матового стекла и молочных испытательных камер |
| Склад модулей | `A C E` / `F O G` / `B □ D` | `F/G` — открытые погрузочные помещения для быстрого пробега. Центральные укрытия `O` закрывают прямую линию запад–восток, оставляя боковые проходы. `B/D` образуют удобные обходы после сдвига. Визуал маркировки контейнеров и окрашенной стали |

Для общего блокаута модулей начальные укрытия ниже заданы в локальных метрах. `(x,z)` — центр прямоугольника, размеры — ширина по X и длина по Z. Зеркальный партнёр меняет знак X. Типы укрытий можно заменить моделью в тех же пределах.

| Модуль | Базовое расположение |
| --- | --- |
| `A/E` | Два разнесённых прямоугольника `(−1,8;−1,45)` и `(+1,8;+1,45)` размером 1,2×1,25. Свободная линия по X=0 |
| `B/D` | Станина `(−1,85;+0,9)` размером 1,1×2,2 и малый блок `(+1,75;−1,45)` 1,05×1,05 |
| `F/G` | Одна короткая коробка `(−2,0;−1,75)` 1,2×1,1 и колонна `(+2,25;+1,75)` 0,65×0,65, центральная зона открыта |
| `C` | Пара `(±1,75;0)` 1,05×1,45, открыта ось север–юг |
| `O` в «Цехе» | Пара `(±1,65;0)` 0,9×1,3. Пьедестал безопасно доступен в центре |
| `O` в «Калибровке» | Четыре пилона `(±1,65;±1,7)` 0,8×0,8. Свободны обе главные оси |
| `O` на «Складе» | Пара `(±1,55;0)` 1,15×2,05. Центральный пьедестал между ними, проходы к востоку и западу огибают блоки |

Эталон сетевого теста. В начальной раскладке «Кранового цеха» шахта в `(r=2,c=1)`. На одном тике команды просят сдвинуть `O` и `F`. При текущем приоритете команды, выбравшей `O`, начинает движение только `O`. На завершении `O` занимает `(2,1)`, шахта — `(1,1)`. Носитель и батарея внутри сохранили локальные координаты, целевая дверь открывается только по новому стыку. Запрос на немедленный обратный ход отклоняется без расхода перезарядки.

Перед моделированием сохранить по каждому модулю исходную карту, контуры укрытий, разрешённые точки респауна и path nodes. Художник укладывается в заданные габариты и оставить двери одинаковыми. Высокий декор над линией зрения отрисовывается отдельно от препятствий. Автоматический валидатор проходит граф всех достижимых шахт, гарантирует корректные стыки, две связи с каждым шлюзом, свободные полосы и возвращение в `O`. Проверить соответствие стартовых линий и путей у зеркальных сторон. Каждая арена должна поощрять свой хороший первый сдвиг.

## 8. Обучение и поведение ботов

Два урока, оба повторяемы из меню.

1. **Пилот**, 60–90 с. Пройти открытую дверь, попасть по тренировочной мишени, взять батарею, проехать в учебной комнате при сдвиге, зарядить ворота.
2. **Штурман**, 60–90 с. Выбрать соседнюю плитку, посмотреть новые стыки, передвинуть комнату с ботом, дождаться его выхода, проложить второй маршрут. Урок показывает и пример запроса, который сейчас невозможен.

Урок работает на ядре, хранит состояние отдельно, имеет пропуск и продолжение. Первый бой помогает короткой подсказкой по контексту. Сменивший роль видит управление до старта раунда.

- Пилот-бот строит путь из разрешённого графа, учитывает видимый коридор и известную позицию батареи. Состояния «к объекту», «прикрыть», «назад с батареей», «обход», «вновь открыть вид». Он целится только в видимого врага, с задержкой и разбросом под сложность. Не подставляется сознательно под урон ради секунд.
- Штурман-бот перебирает до четырёх законных сдвигов. Сравнивает улучшение дистанции своего носителя к цели, открытие выхода своему пилоту и ухудшение пути последнего видимого соперника. При частом повторении даёт штраф сдвигу. Использует ту же поле зрения, кулдаун и цифровую команду. При пинге союзника повышает приоритет отмеченной комнаты, если сдвиг полезен.
- Лёгкий режим дольше реагирует и меньше учитывает риск, сложный чаще синхронизируется с метками и огнём. Скорость, урон, обзор, стартовые сведения и возможности ролей те же.
- Прогнать обе роли и смешанный ростер во всех раскладках, включая матч двух людей в одной команде против ботов. Патологическое повторение двух сдвигов и неслучившиеся доставки требуют настройки, а не симуляции успешного завершения.

| --- | --- |
| Старт | `roomId, startCommandId, roster, teams, initialRoles, settings, rulesVersion, contentVersion`. Один start ID — один матч |
| Ввод пилота | `seq, roundId, controllerEpoch, moveX, moveZ, aim, fireHeld` плюс импульсные действия взятия/метки с ID. Сервер ограничивает диапазон, частоту и окно |
| Команда штурмана | `actionId, roundId, expectedBoardRevision, roomId, controllerEpoch`. Возврат ack и причиной отказа, можно безопасно повторить |
| Пространства | Таблица `cell → roomId`, шахта, переход `from/to/startTick/endTick`, две среды шлюзов, текущие открытые стыки |
| Вид клиента | Таймеры, свой контроллер, публичные комнаты и их движение, разрешённые союзники/враги, разрешённая батарея, приоритет и cooldown, счёт, события, `lastAcceptedSeq` |
| События | Сдвиг принят/завершён, видимая атака, урон получателя, появление, батарея/доставка, завершение раунда, результат. Фильтр звука и игрового payload один |

Матч сериализует один серверный владелец. Принимая сдвиг, проверяет фазу, роль, положение шахты, резерв, ревизию и таймер. Привязку пересечения дверей делать непрерывной между шагами, стрельба работает из канонического положения тика. В v1 сервер считает луч без перемотки истории. Подобрать скорость и размеры под реальный RTT до 120 мс. Клиент интерполирует удалённых акторов и предсказывает собственный ход. Как только видимость отозвана, убрать тело и следы, которые следуют за его живой позой. Последний маркер неподвижен до разрешённого обновления или истечения. Сдвиг начинается после ack, собственное движение пересогласуется по `spaceId` и связанному тику. Пропуск вывода промежуточного snapshot возможен, события доставки и смены раунда имеют отдельные ID.

Матч пишет SQLite на границах фаз, при начале и завершении сдвига, взятии и сбросе батареи, доставке и результате. Для дискретной команды, влияющей на батарею или плитку, сначала сохранять состояние и квитанцию, затем отвечать. Высокочастотный ввод этим не блокируется. Активный снимок раз в **2 с** фиксирует роли, тела, boardRevision, локальные координаты батареи, начало и конец переезда, таймеры, квитанции и seed. Тики с зажатой кнопкой хранятся в оперативной памяти. Изолированный тест падения начинает с последнего целого checkpoint, показывает восстановление и **5 с** общей подготовки, возвращает остатки таймеров. Подтверждённый результат сохраняется целой транзакцией. Штатный выход сервера сначала фиксирует состояние. Протокол reconnect обновляет сессию и view, никакой старый ack не запускает второй сдвиг/очко.

Цели профилирования. Комнаты обрабатываются независимо. Нагрузка шесть активных матчей 3×3 с ботами и несколькими реальными браузерами. p95 обработки общего тика до 75% от **33,3 мс**, без накопления невыполненных тиков. При блокировке запросов отделить тики ограниченным пулом workers и оставить единственного владельца комнаты. Первый вход ≤5 МБ внешних файлов из пустого кэша, одна арена загружается по выбору, ≤130 draw calls в low, целевые 60 FPS на проверенном компьютере и ≥30 FPS на задокументированном мобильном. Тестировать Safari, Chromium и реальный телефон, записывать профиль и устройство.

## 11. Контрольный лист на финальную сборку

- **Блок-аут и правила.** Обход по краям при шахте, конкурирующие сдвиги на одном тике, запрет обратного, дрон на пороге и внутри модуля, батарея в руках/на полу/на пьедестале, движение с закрытыми дверями, таймер возврата. Ни один из трёх уровней не блокирует доставку из-за планировки.
- **Бой.** Обмен двумя смертельными импульсами, запрет урона своему, щит, остановка на стене, перенос под огнём, падение носителя на последнем тике, повтор взятия, прерывистая зарядка, ничья и один решающий раунд. Финальный счёт соответствует порядку тика.
- **Права и видимость.** Пилот без права сдвига, штурман без управления чужим пилотом, посторонняя сессия, две вкладки места, смена роли и эпохи, чужая метка и скрытый противник отсутствуют в snapshot, событиях, звуке. Для проверки использовать инструментальные подписки в разрешённых комнатах.
- **Онлайн.** Два независимых клиентских профиля плюс боты, отдельный 3×3, повтор кнопок и lost ack, вход с приглашения, задержка 120 мс, краткое отключение, продолжение после рестарта в середине переезда, сверка одного результата. Штатные тестовые приглашения через принятый безопасный транспорт.
- **Плейтест.** Минимум по две полные игры 2×2 и 3×3 с людьми на разных ролях. Протокол отдельно фиксирует время ожидания штурмана, понятность дверей, долю завершённых доставок, роль первого сдвига, темп и причины ничьих. Проверить обе стороны каждой карты и задокументировать факт реальной игры.
- **Клиент.** Safari, Chromium, 1366×768, 1920×1080, 844×390, телефон, масштаб текста, переназначение, low, 2D-переход и восстановление WebGL. Реальное прослушивание трёх типов звука, включая дверь и подтверждение батареи.
- **Общая сборка.** `npm ci`, `npm run check`, `npm run build:all`, `npm run platform:smoke`, `npm run portal:e2e` и целевой браузерный сценарий игры. Существующие игры открываются и сохраняют свои активные матчи.
- **Художественная идентичность.** Проверены локальное лобби, HUD двух ролей и схема результата. Оригинальные дроны, рельсы и звуки переноса связывают экраны в один продукт. Рядом с другими играми «Сдвиг» узнаётся по сетке, угловой типографике и форме плит. Все обязательные 3D-файлы в релизном клиенте.
- **Релиз.** Отчёт об исходном и итоговом SHA, ссылках CI и получившейся сборке, лицензиях, измерениях. Сборка артефакта и факт доставки подтверждаются отдельно. Продолжение текущей комнаты после замены процесса проверить изолированно. Для уже выпущенных данных проверить совместимый образ отката и порядок резервирования до обновления.
