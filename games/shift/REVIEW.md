# Сдвиг — независимое ревью клиента и интеграции

## Метод и область

Прочитаны предоставленное полное ТЗ, `src/ui/`, рендер, фильтр `viewForSeat`, слой общего WebSocket, адаптер runtime и места подключения в портале. Выводы ниже получены из этих файлов. Ревью не засчитывает полный сыгранный матч или новый цикл браузерной приёмки. Пока выполнялось чтение, основная сборка и браузерные прогоны других исполнителей продолжались отдельно.

Первоначальный обзор не менял код. Для ошибки прицела отдельно исполнен настоящий `roomOrigin` из геометрии с заданным тестовым состоянием; численный результат приведён ниже. Последующие порученные исправления рендера и реальные адресные проверки записаны в конце отчёта. Остальные открытые сценарии — воспроизведение, выведенное из кода, и указания для проверки после исправления. Они не выдаются за лично сыгранные браузерные эпизоды.

## Найденные дефекты

### REV-01 · P1 · Прицел расходится с курсором во время обычного переезда

**Места:** `src/render/ShiftRenderer.tsx`, функции `frame` и `worldPoint`; `src/ui/Shift.tsx`, callback `onWorldAim`.

Рендер показывает комнату на `smoothTick = view.tick + min(2, elapsed * 0.03)`. Координата курсора преобразуется в мировой план показанной сцены. Клиент вычисляет направление от `worldPosition(..., view.tick)`. Поправка из показанного положения комнаты в каноническое существует только при `reducedMotion=true`, хотя рассогласование есть и при обычной интерполяции.

**Исполненный численный пример:** O переезжает из 4 в 7, интервал 0–17. Снимок на тике 5, показанный тик 7, пилот в локальном центре целится на 5 м строго на восток. Настоящий `roomOrigin` возвращает каноническую позицию `(8, 10.352941176470589)` и показанную `(8, 11.294117647058822)`. Без поправки направление получается **10.660348°** вместо 0°. Та же поправка, которая уже используется в reduced motion, даёт практически 0°.

**Исправление:** применять перевод показанного origin в канонический для собственного пилота в движущейся комнате независимо от reduced motion. Не изменять физическое движение или серверное положение цели. Не применять поправку к выбору комнат штурманом или к мини-карте, которая использует тактический выбор.

**Проверка:** в 2D и 3D провести горизонтальный/вертикальный прицел внутри переносимой комнаты при нескольких промежуточных тиках; направление относительно локального пилота должно сохраняться. Повторить reduced motion. Это блокирующий дефект основного сценария боя при переезде.

### REV-02 · P2 · Отложенный звук способен начаться после выключения громкости или выхода

**Статус: исправлено; фактические адресные проверки Web Audio — в разделе «Последующее исправление аудио».** Описание ниже фиксирует первоначальный дефект.

**Место:** `src/ui/audio.ts`, обработка `buffer(name).then(...)` и вложенный звук двери.

Обработчик события запоминает `preferences.volume`, а затем ждёт fetch/decode. У эффекта нет отмены этих обещаний на размонтирование, и перед `source.start()` не проверяются актуальная громкость, актуальность события и активность компонента. Ограничение возраста события проверяется только до загрузки. Аналогично устроена загрузка двери.

**Сценарий для воспроизведения:** задержать первый запрос `pulse.wav`; сделать выстрел; выставить «Сигналы» в 0 или выйти в меню; разрешить ответ WAV. Текущий код начинает звук с прежней ненулевой громкостью. Это вывод из жизненного цикла обработчика, не заявленное реальное прослушивание.

**Исправление/проверка:** общий актуальный уровень сигналов и отмена/проверка поколения сцены; повторная проверка возраста события перед воспроизведением. В инструментальном браузерном тесте после mute/unmount задержанный ответ не должен приводить к новому `AudioBufferSourceNode.start()` с ненулевым уровнем.

### REV-03 · P2 · Онлайн-игра только с клавиатурой не включает звук

**Места:** `src/ui/Lobby.tsx`, `src/ui/Shift.tsx`, `src/ui/audio.ts`.

Локальная практика вызывает `unlockAudio()` в `start`. Онлайн-лобби этого не делает. В `MatchShell` единственная привязка разблокировки — `onPointerDown`. Новый онлайн-контекст, управляемый Tab/Enter, стрелками и Space, может всё время оставаться без созданного/запущенного AudioContext.

**Исправление/проверка:** использовать доверенный клавиатурный жест в игровом экране либо готовность/старт лобби. Проверить новый браузерный контекст без указателя: клавиатурный старт и сдвиг должны перевести аудиоконтекст в running. Проверка API не заменяет прослушивание.

### REV-04 · P2 · Стрелки выбирают комнату, но Enter может активировать старую кнопку

**Место:** `src/ui/Shift.tsx`, глобальный обработчик `down`.

Стрелки штурмана меняют выбранную комнату, не переводя фокус на игровое поле. Обработка Enter специально пропускается для любого `HTMLButtonElement`. Поэтому после закрытия настроек, когда фокус вернулся на ⚙, ArrowUp выбирает модуль, а Enter снова открывает настройки. Аналогично Enter на кнопке комнаты повторяет выбор вместо подтверждения сдвига.

**Исправление/проверка:** при использовании стрелок для выбора перенести фокус в сцену либо отдельно определить режим клавиатурного выбора. Сохранить обычную активацию кнопок Enter. Проверить последовательность «настройки → закрыть → стрелка → Enter», а также выбор комнаты мышью.

### REV-05 · P2 · Центральный HUD сообщает неправильную комнату батареи

**Место:** `src/ui/Shift.tsx`, `.shift-pilot-status`.

Если пилот жив и не несёт батарею, строка всегда показывает «Найдите батарею в O / Find the battery in O». Это неверно после сброса в другой комнате и когда батарею несёт команда. Боковая панель уже использует правильный `BatteryView`.

**Исправление/проверка:** формировать обе подсказки из одного разрешённого вида батареи: свободная — известный модуль, скрытый носитель — только команда, свой носитель — доставка. Не придумывать точку скрытого носителя. Проверить сброс вне O и скрытую чужую переноску.

### REV-06 · P2 · Часть сенсорных целей лобби меньше 44 CSS px

**Место:** `src/ui/shift.css`, `.shift-seat-controls select` и `.shift-seat-remove`.

Выбор команды/роли явно переопределяет высоту на 32 px; кнопка удаления имеет ширину 30 px. Позднее правило минимального размера 44 px охватывает игровые кнопки, но не эти элементы лобби. ТЗ §7.2 задаёт сенсорные цели от 44 CSS px.

**Исправление/проверка:** обеспечить минимум 44×44 для этих элементов, в том числе coarse pointer, не закрывая соседние цели. Подтвердить `getBoundingClientRect` в лобби при 844×390 и увеличенном тексте. Текущий вывод основан на CSS, а не на измерении физического экрана.

### REV-07 · P2 · В перерыве отсутствует схема пути батареи, ключевые события могут исчезнуть

**Места:** `src/ui/Shift.tsx`, intermission и `Result`; `src/core/engine.ts`, выдача `events`.

В перерыве выводятся последние три отфильтрованных текстовых события из `view.events`, а в финале — таблица и текстовая цепочка. Схемы пути батареи нет. Кроме того, `view.events` ограничен 36 событиями вместе с выстрелами: при активном бою более ранний решающий сдвиг или взятие может пропасть до начала перерыва. ТЗ §5 требует путь последней батареи и три решающих события по правилам видимости; после финала разрешён общий журнал.

**Исправление/проверка:** хранить отдельный ограниченный набор значимых событий/известных точек батареи для командной сводки, не раскрывая скрытую переноску; показывать схему с разрывами на неизвестных отрезках. Финальная сводка может использовать только уже закрытый общий журнал. Проверить длинную перестрелку между сдвигом, взятием и доставкой. Это функциональный пробел ТЗ, а не замечание к стилю оформления.

## Что не показало дефект в проверенном коде

- Мини-карта меняет только ракурс/роль представления собственного `ShiftView`, а не запрашивает вид штурмана противника. Список разрешённых акторов сохраняется; увеличение мини-карты не расширяет обнаружение.
- Аудио получает только персональную ленту `view.events`. Панорамирование вычисляется из уже разрешённых событий. Цикл зарядки использует союзников, чей прогресс доступен команде.
- `getPredictedSelf` меняет только собственные `spaceId/x/z/aim`; здоровье, щит и владение батареей остаются авторитетными. Предсказание вызывает ту же `movePose`, учитывает закрытые двери и не действует во время recovery/смерти/неактивной фазы.
- Полный `journal` отправляется только при `phase === 'finished'`. Это разрешено ТЗ §5. Во время матча HP и позиции скрытых врагов, чужие пинги и приватный счёт перевозок батареи не добавляются интерфейсом.
- Общий WebSocket проверяет origin/host, сессию, членство, matchId, wire version и актуальность эпохи. HTTP-вид повторно проходит членство и `viewForSeat`. Выбор команды и роли доступен хосту только в лобби; runtime фиксирует состав при старте.
- Финальный экран использует серверные `winner/score/rounds/stats`, различает доставку и таймаут, переводит фокус внутрь диалога и удерживает Tab на его элементах. Кнопка реванша не назначает победителя и возвращает комнату в лобби с новой готовностью.

Не выполнялись новые полные матчи, физический сенсорный тест, Safari, прослушивание, проверка production HTTPS или выпуск. Изображение финала обычного матча на момент просмотра файлов ещё не было доступно; искусственный результат не создавался. ## Последующее исправление рендера

**REV-01 закрыт изменением исходника и численной регрессией.** `canonicalAimPoint` в `src/render/presentation.ts` переводит показанный origin комнаты в канонический для пилота при обычном и уменьшенном движении. Штурман и пилотская мини-карта сохраняют показанные координаты выбора. Четыре стороны прицела проверены на показанных тиках 0, 5, 5,48 и 7; исходный `ShiftView` не меняется.

**Завершение принятого переезда в перерыве.** После исправления ядра `presentationTick` продолжает ограниченную интерполяцию при `phase=intermission` и существующем `motion`. Восстановление останавливает её, законченный матч и перерыв без движения не экстраполируются. Reduced motion сохраняет исходную показанную клетку. Это изменение только представления принятого сервером действия.

### REV-08 · P1 · Неподвижная мышь не обновляла прицел при движении пилота — исправлено

Этот дефект проверен реальным Chrome Headless Shell 159 на визуальном стенде с настоящими командами `stepMatch`, до изменения и после него. В 2D курсор оставлен в одной точке, пилот прошёл 0,766667 м на юг. До исправления callback прицела вызывался один раз, угол оставался около 0 вместо −0,2502007 рад: ошибка около 14,34°. После исправления в том же сценарии получен точно ожидаемый угол, ошибка 0.

Рендер сохраняет последнюю позицию мыши и заново преобразует её после обновления проекции каждого кадра. Обновление действует только для пилота. Касание, уход мыши из сцены без захвата или потеря фокуса освобождает мышиное управление, чтобы оно не заменяло сенсорный стик.

Финальная адресная проверка дала:

| Сценарий | Наблюдаемый результат |

| 2D, неподвижная мышь, пилот движется | Ожидаемый и фактический угол −0,25020069960451946 рад; ошибка 0 |
| Обычная 3D-камера следует пилоту | Угол до и после совпал; ошибка 0 |
| Фиксированная 3D-камера reduced motion | Ожидаемый и фактический угол −0,5600076085824928 рад; ошибка 0 |

Проверки `presentation.test.ts`: **4/4 прошли**. После окончательной правки прошли `npx eslint games/shift/src/render` и `npx tsc --noEmit --pretty false`. Исходники изменены только в `src/render/ShiftRenderer.tsx`, `src/render/presentation.ts` и `src/render/presentation.test.ts`. Сырые адресные результаты: `.qa/shift-art/aim-before.log`, `aim-after.log`, `aim-final.log`. Полных матчей к счёту приёмки эти тесты не добавляют.

## Последующее исправление аудио

**REV-02 закрыт изменением `src/ui/audio.ts` и восемью реальными адресными браузерными проверками.** Сигналы принадлежат конкретному поколению сцены: смена раунда/эпохи, выключение сигналов или размонтирование отменяют ожидающие сигналы и останавливают уже созданные узлы. Перед запуском проверяются текущая громкость, активность аудиоконтекста и компонента, поколение, раунд, эпоха и свежесть события. Предел свежести действует и по прошедшему времени без новых снимков. Загрузка файлов параллельная, запуск сохраняет подтверждённый порядок событий. Дверь и механический сигнал входят в ту же отменяемую группу. Изменение ненулевой громкости обновляет уже играющие сигналы.

Цикл переезда теперь продолжается, пока существует принятый `motion`, включая межраундовый перерыв. Recovery останавливает цикл; после восстановления он возобновляется только при ещё существующем движении, а стыковка прекращает его. Это согласовано с завершением переезда ядром в перерыве.

Изолированный React-стенд импортировал настоящий `useShiftAudio` и ядро; события выстрела, попадания, доставки и сдвига получены от ядра. Для проверки жизненного цикла стенд управлял громкостью/размонтированием и состояниями intermission/recovery. Первый WAV задерживался перехватом браузерного запроса. Настоящие `AudioContext`, `decodeAudioData`, `AudioBufferSourceNode` и `GainNode` исполнялись в Chrome Headless Shell 159.0.8154.6; инструментирование записывало вызовы `start`/`stop`, длительность буфера и коэффициент усиления, не заменяя узлы имитацией. Каждый сценарий использовал отдельный браузерный контекст.

| Адресный сценарий | Фактический результат |
| --- | --- |
| Задержать `pulse.wav`, выключить и снова включить сигналы до ответа | Старый сигнал не стартовал; новый выстрел после ответа дал ровно один старт |
| Во время загрузки изменить уровень с 0,5 на 0,2 | Выстрел начался с актуальным gain ≈ 0,05, то есть 0,2 × 0,25 |
| Размонтировать сцену до ответа WAV | Новых стартов нет |
| Задержать WAV на 800 мс без нового snapshot | Просроченный сигнал не стартовал |
| Выключить сигналы во время доставки | Реально стартовавший буфер 0,849977 с получил `stop` и завершился |
| Размонтировать сцену во время доставки | Активный узел получил `stop` и завершился |
| Сдвиг → intermission → recovery → восстановление → стыковка | Первый цикл не прервался на intermission, остановился на recovery; новый цикл стартовал после восстановления и остановился при удалении `motion` |
| Задержать звук выстрела при уже загруженном попадании | До ответа не стартовал ни один сигнал; затем стартовали сначала pulse 0,18 с, затем hit 0,129977 с |

Результат: **8/8 сценариев, ошибок JavaScript нет**. `npx eslint games/shift/src/ui/audio.ts` и общая проверка `npx tsc --noEmit --pretty false` прошли. Временные исполняемые сценарии и полный журнал: `.qa/shift-audio/`, машинный результат — `report.json`.

Это инструментальная проверка настоящего браузерного аудиографа, **не реальное прослушивание**, не физическое устройство и не дополнительные полные матчи. Разблокировка звука клавиатурой (REV-03) относится к отдельному исправлению интерфейса.
